# 搜索页筛选排序局部刷新 - 任务列表

## 🚩 Milestone 1: 基础设施与状态层重构 (PR 1: 基础骨架)

**目标**：搭建好底层的状态流转和样式基础。开启 Feature Flag 不改变现有渲染，但状态和 URL 已可同步。

**评审重点**：CSS 是否影响全局？路由拦截是否破坏了现有的页面跳转逻辑？

### Task 1: UI/UX 规范与样式引擎层 (CSS/Design) ✅
- 产出 CSS 交错动效类（.is-leaving, .is-entering 等，强制使用 transform/opacity 触发 GPU 加速，避免重排）
- 实现 CSS 变量 `--delay` 控制交错延迟，并设置最大交错限制（如前 10-15 个卡片，防止长列表动画拖沓）
- 补充设计与实现：加载骨架屏、空状态缺省页、网络异常页的样式
- 落实 @media (prefers-reduced-motion: reduce) 无障碍动画回退方案（直接将 transition 设为 0ms 或 1ms）
- 动效参数严格对齐：时长 300ms，缓动 ease-out，基础延迟 30ms

### Task 2: 数据层与状态机抽象 (State Management) ✅
- 引入 Feature Flag (enable_partial_refresh) 控制新旧渲染逻辑无缝分流
- 拆分重构：解耦 renderSearchResults（局部渲染核心）和 updateFilterButtons（按钮激活态）
- URL 状态同步：核心检索条件改变使用 history.pushState，非破坏性微调（如原地的分页加载）使用 history.replaceState
- 全局监听 popstate 事件，实现浏览器后退/前进时的数据反向驱动
- **🛡️ 滚动冲突防御**：初始化时设置 `history.scrollRestoration = 'manual'`，接管浏览器的默认滚动恢复，防止后退时页面闪跳
- 逻辑规整：任何筛选条件变更时，强制重置分页器状态至 Page 1

## 🚩 Milestone 2: 核心调度与闭环渲染 (PR 2: 核心 MVP)

**目标**：打通局部刷新主流程，包含竞态处理、DOM 更新与异常闭环（保障断网时不白屏、不卡死）。

**评审重点**：内存是否有泄漏？连续点击并发请求是否被正确 abort？

### Task 3: 网络层与并发调度 (API & Orchestration) ✅
- 引入 AbortController 终结连续点击的竞态请求（确保只有最后一次请求的 Promise 被 resolve）
- 引入 SWR (Stale-While-Revalidate) 短时内存缓存机制：参数哈希命中时直出数据，跳过 Loading 阶段
- 实现 Promise.all 协同调度：并行等待 "CSS transitionend (离开动效)" 与 "API Response (接口数据)"
- 骨架屏防闪烁 (Debounce Loading)：接口请求耗时 > 200ms 且动效离开完毕时，才允许挂载骨架屏
- **🛡️ 编写核心 Unit Test**：重点测试竞态拦截逻辑与 SWR 缓存命中率

### Task 4: 视图层局部渲染与异常流 (View & Fallback) ✅
- 建立严格的渲染状态机：IDLE -> UPDATING -> ENTERING -> IDLE
- **🛡️ 内存与重排优化**：使用 DocumentFragment 批量组装新节点；在销毁旧 DOM 前，清理挂载其上的非代理事件或第三方组件实例
- 引入图片 LCP 优化：监听首屏核心卡片（前 3 张）img.onload 结束后，再触发 ENTERING 入场动画
- 筛选/排序按钮容器全面改造为事件代理 (Event Delegation)
- **🌟 异常流闭环拦截**：
  - 断网/接口 5xx 时：中断渲染状态机，回退 Task 2 更改的 URL 与按钮高亮状态，并挂载"重试"异常页
  - 数据为空时：拦截列表渲染，平滑过渡至"无匹配结果"缺省页

## 🚩 Milestone 3: 体验打磨、监控与验收 (PR 3: 上线准备)

**目标**：无障碍接入、埋点上报，以及保障极端场景下不翻车的全面自动化/手工测试。

### Task 5: 焦点流转与无障碍体验 (A11y Polish) ✅
- 列表容器动态添加 aria-live="polite" 与 aria-busy="true/false"，供屏幕阅读器精准播报状态
- 焦点转移管理：旧节点销毁后，将 focus 平滑引流至新列表容器或首个可交互的商品卡片
- 视图自动复位：在 ENTERING 动画触发前一帧，平滑将页面滚动条重置回列表容器顶部

### Task 6: 性能度量与埋点监控 (Telemetry) ✅
- 业务埋点：上报 Filter_Applied 点击事件（必须附带当前聚合的筛选项参数）
- 性能监控：利用 Performance API 上报 Time_to_New_Results 真实体感耗时（从点击发生到 ENTERING 结束）
- 稳定性监控：记录 Fetch_Abort_Count (竞态触发率) 与 Fallback_Error_Count (降级异常率)

### Task 7: QA 与端到端回归验证 (E2E Testing) ✅
- 验证 Feature Flag 的无缝开启与关闭（不应引起页面崩溃）
- **🛡️ SEO 与首屏验证**：开启开关后，刷新页面，验证服务端的首次 HTML 直出（SSR）不受破坏
- 验证动效流畅度（Chrome DevTools Performance 录制，目标不低于 50fps，无 Long Task 阻塞）
- 极限压力测试：模拟"狂按"筛选键、快速连击浏览器后退/前进键，验证状态机不乱套
- 降级测试：OS 开启"减弱动态效果"测试；DevTools 模拟 3G 弱网看骨架屏；模拟 Offline 看异常回滚
- 纯键盘交互测试：仅使用 Tab 和 Enter 走通完整的筛选与排序流程

3. **PR 3 合并后**：QA 验收完毕，正式对 10% 用户开启灰度，观察 Task 6 收集到的性能与异常指标，若一周无严重客诉，全量推开。
